# 知识点讲解补全 — 设计文档

日期: 2026-07-26
状态: 待用户审阅

## 背景与目标

用户实际刷题后反馈：部分真题解析（`explanation_zh`/`explanation_en`）里出现的概念或术语，在对应知识点页面的「详细讲解」(`concepts`) / 「高频词汇」(`vocabulary`) 区块里找不到，做题时要跳出页面另外查资料，体验不好。

目标：确保每个知识点页面的「详细讲解」+「高频词汇」区块，覆盖该知识点下所有真题解析里出现过的概念/术语——用户做完题回到讲解区，任何题目提到的东西都能在本页找到解释。

## 范围

**这次做什么：**
- 审查 11 个知识点的全部真题（`topics/*/questions.js`，共 93 题）解析内容
- 对每道题解析开头的 `【知识点】A + B` 标签、以及解析全文里提到但未标签的概念/术语，逐一核对是否已存在于该知识点 `meta.js` 的 `concepts`/`vocabulary` 数组中（允许中英文/表述变体的模糊匹配）
- 把真题中出现、但讲解页没有的概念/术语，直接补充进对应的 `concepts`（有公式/推导的）或 `vocabulary`（术语/固定表达）数组，和现有条目同一种格式
- 新增内容必须严格从该知识点自己的真题解析原文（`explanation_en`/`explanation_zh`，即官方解析的中文转述）中提炼，不额外引入解析原文之外的说法，避免凭通用知识编出和真实解析对不上的内容

**这次不做：**
- 不整理计算器按键操作步骤（属于具体解题过程，留在题目解析里即可，不重复搬进讲解页）
- 不改动渲染代码（`js/topic-page.js` 等）——`concepts`/`vocabulary` 已是无长度限制的循环渲染，加条目不需要改代码
- 不修 docx 原始导入遗留的乱码/OCR 问题（如 `explanation_en` 里的符号丢失），除非它直接挡住了本次审查的判断

## 处理方式

11 个知识点相互独立（各自的 `meta.js`/`questions.js` 互不依赖，渲染时也是逐文件加载），按知识点拆成 11 个独立小任务并行处理：

1. 读取该知识点的 `questions.js` 全部题目解析 + 现有 `meta.js` 的 `concepts`/`vocabulary`
2. 列出解析中出现、但页面缺失的概念/术语清单
3. 为每一条缺失项，从题目解析原文中提炼公式/定义，写成新的 `concepts` 或 `vocabulary` 条目，追加进 `meta.js`（不改动已有条目，不重排数组顺序）
4. 完成后用浏览器本地打开该知识点页面，确认页面正常渲染、无 JS 报错，抽查新增条目内容与来源题目解析一致

## 验证

- 每个知识点处理完，本地打开对应 `topics/<id>/index.html`，确认「详细讲解」「高频词汇」区块正常展开、无报错
- 抽查若干新增条目，对照其来源题目的 `explanation_en`，确认公式/定义没有编造或抄错
- 全部完成后，最终过一遍全部 11 个页面，确认没有遗漏题目对应的知识点
